IoTSharp Local Workbench

IoTCoWork

开源本地工作台外壳。它把 IoT 工程建模、调试、生成、发布和本地 AI Gateway 连接放在一个桌面工作面里，承担“云端思考、本地干活、边缘执行”中的本地层。

Capabilities

面向 IoT 工程师的本地工作台骨架

01

三栏工作区

左侧会话与任务，中间工作画布，右侧工程上下文、产物、工具、日志和风险。

02

本地设置中心

统一管理外观、模型、本地网络代理、更新、快捷键和能力中心入口。

03

能力中心

预留智能体、技能、指令、挂钩、MCP 服务器和插件的本地 UI 插槽。

04

AI Gateway 连接

通过本地代理连接用户配置的 AI Gateway，不在开源外壳内实现商业账号或计费。

05

工程上下文

围绕 workspace、边缘目标、输出位置、审批模式和工具运行组织任务上下文。

06

桌面宿主

IoTCoWork.App 托管本地 API 和 WASM 静态资源，并用 NativeWebHost 打开桌面窗口。

Workbench

开源仓库只保留本地外壳和扩展点

IoTCoWork.App桌面宿主、本地 API、更新、快照和 AI Gateway 代理。
IoTCoWork.WorkbenchBlazor WebAssembly 工作台界面和本地状态。
NativeWebHost跨平台 Native WebView 宿主抽象与 Windows 实现。
IoTSharp / IoTEdge工作台面向主平台和边缘基座提供本地入口。

不接管设备管理 设备、遥测、告警和规则仍属于 IoTSharp 主平台。

不承载商业账号 租户、计费、钱包、License 和付费模板由上层商业模块注入。

只做本地连接 Token、代理和 AI Gateway 地址由用户在本机配置。

保留插件插槽 外部贡献通过公开 UI 插槽和契约进入工作台。

Extension

从开源外壳开始扩展自己的工作流

默认开发流程会构建 Blazor Workbench，并由 IoTCoWork.App 作为本地桌面宿主加载。GitHub Pages 文档来自本仓库 `docs/` 目录。

git submodule update --init --recursive
dotnet build IoTCoWork.sln -m:1

dotnet run --project IoTCoWork.App -f net10.0-windows
dotnet run --project IoTCoWork.App -f net10.0 -- --headless
IoTCoWork is the local workbench shell of the IoTSharp ecosystem. iotsharp.net
