# IoTCoWork 语义建模 UI 信息架构

> D1 目标：把工作台从“点表编辑器”升级为 Semantic Workspace 建模面。开源工作台只提供本地 UI 骨架、公开工程模型占位和插件贡献点，不实现商业账户、余额、充值、租户、License 或付费模板逻辑。

## 1. 一等对象

语义建模页围绕四个对象组织：

| 对象 | 层级 | 用户要完成的事 |
| --- | --- | --- |
| 资产 | L2 | 建立 site / area / line / device / component 层级和 `assetPath`。 |
| 点位 | L1 | 为每个值补齐 `semanticId`、显示名、量纲、单位、数据类型、访问权限、质量和资产归属。 |
| 绑定 | L0 -> L1 | 把 Modbus register、MQTT Topic、OPC UA NodeId 等来源绑定到语义点。 |
| 工艺关系 | L3 | 表达上下游、派生变量、状态、报警和控制策略关系。 |

点表仍然可以作为导入来源，但不再是工作台的主模型。

## 2. 页面结构

- 顶部：工作台品牌、返回总览、资产/点位/绑定/工艺锚点导航。
- 左侧：建模对象导航和开源边界提示。
- 中间：Semantic Core 摘要、资产树、点位表、绑定列表、工艺关系列表、建模流程。
- 右侧 Home 上下文面板：默认展示资产、点位、绑定、工艺四类 Tab，再展示工程树、产物、任务、工具、日志和风险。

## 3. 信息层级

建模时的优先顺序：

1. 建立资产路径。
2. 补齐点位语义字段。
3. 绑定协议来源。
4. 维护工艺关系。
5. 触发本地或上层注入的生成任务。

## 4. 开源边界

- 不在工作台外壳中实现设备注册、心跳、配置、命令或固件管理。
- 不接收、转发、落库真实业务遥测、属性、事件或告警。
- 不加入余额、充值、商业账户、租户策略、License 或付费模板逻辑。
- 设备维度入口只能作为跳转到用户自有 IoTSharp 实例的引用。

## 5. D1 验收点

- 左侧导航存在“语义模型”入口。
- `/semantic-modeling` 页面能展示资产、点位、绑定、工艺关系四类建模对象。
- Home 右侧上下文 Tab 默认从语义对象开始。
- UI 文案以 Semantic Workspace、资产、点位、绑定、工艺关系为主，不以裸点表作为核心。
- 开源工作台文案不包含余额、充值、租户、License、付费模板等商业计费概念。
